A template is the stage table with one repo's manifest values filled in. Every value below comes from
.sme/manifests/repo-infra-central.md or from an earlier row's output, never from memory. Each row that runs a
script is one intake record for `atpy do`; the booleans a row consumes are named beside it.

Parameters (from the manifest; the slug names it):
- repo: infra-central
- default_branch: main; branch_pattern: KEY-desc; mr_target: main
- project: amwell/platform/infrastructure/infra-central; shape: single-plan-apply
- layer: the `- layer:` line whose dir the changed paths fall under (12 lines, accounts/*); `--paths` resolves it

## Stages
| stage | step | how | consumes |
|---|---|---|---|
| intake | context | `atpy sme brief KEY` (a lookup, no record) | none |
| intake | repo and MR state | `atpy gather KEY --repo infra-central` | none |
| plan evaluation | plan | agent drafts W-nn; `atpy sme store write amendment` for changes; `atpy sme approve W-nn --ticket KEY --by` on the user's yes | none |
| plan execution | latest default branch | `atpy repo pull infra-central` | none |
| plan execution | branch | `atpy repo branch-start KEY --repo infra-central --title "<plan title>"` | none |
| plan execution | change | agent edits under the touches gate; `terraform fmt -check -recursive -diff` on the layer | none |
| plan execution | local check | `atpy repo validate-local --repo infra-central`; `terraform init -backend=false && terraform validate` in the layer | none |
| plan execution | push | `atpy repo push infra-central` | force_push_is_human, approval |
| plan execution | watch | `atpy gitlab watch <id from gather> --repo infra-central --paths <changed>`; quote the VERDICT and the "Plan:" line | read_trace_only_on_fail, human_plays_apply |

| end after merge | verify | `atpy gitlab watch <default-branch pipeline id> --repo infra-central --layer <dir> --until apply`; the human plays the apply job; the "Apply complete!" line must match the plan | verify_after, human_plays_apply |

| end execution | post and close | `atpy jira comment KEY "<plan and apply lines>"`, `atpy jira transition KEY --status "<name>"` | post_needs_approval, approval |
