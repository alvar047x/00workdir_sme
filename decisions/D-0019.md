**Decided:** Read a ticket with `at jira fetch KEY`, then read `automation_tools/tickets/KEY/ticket-review.md`. It carries summary, status, type, risk, deadline, description, and every comment. Move status with `at jira transition KEY --status "<name>"`; set required fields first with `at jira set-fields KEY`; comment with `at jira comment KEY "<text>"`; begin work with `at jira start KEY`.

**Because:** The review file is the one place with everything an agent needs. Parsing the snapshot JSON by hand cost four tool calls per ticket. Transition IDs are resolved by name inside the tool, so the ID tables in the old steering are not needed in context.

**Applies when:** Any read, status change, or comment on a Jira ticket.

**Does not apply when:** Bulk sprint views, which use `at jira sprint` and `at sprint analyze`.
