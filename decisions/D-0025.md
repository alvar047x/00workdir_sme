**Decided:** Any step that waits on a pipeline is one call of the watch script with --repo from the manifest, and the reply quotes its verdict line. Red jobs are classified from the jobs API fields (allow_failure, failure_reason, status); a trace is read only for a job the verdict names as blocking. A repo whose Watch block lacks project or shape gets an intake step before any watch step, never an improvised command.

**Because:** On DVPS-6622 the monitor verb polled the wrong plan and apply pair for two hours, the pipeline verb read 50 of 188 jobs, and error evaluation was improvised from traces the jobs API already classified (S-49: two retryable, two informational, nothing blocking, no trace needed).

**Applies when:** Backs the boolean read_trace_only_on_fail. Any plan step, prompt or scout that waits on, checks or reports a GitLab pipeline or job.

**Does not apply when:** A one-line pipeline id lookup that precedes the watch call, and a repo whose manifest Watch shape is none.

**Replaces:** none
