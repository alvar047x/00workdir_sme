**Decided:** Open merge requests through the tooling path: push the work branch with `at repo push`, then open the MR from the standard MR template with the Jira key in title and description. Never draft an MR by hand in the GitLab UI. When `at gitlab mr-create` exists this decision is superseded to name it.

**Because:** Hand-opened MRs are the common source of missing Jira linkage. The old steering cited `at.py gitlab mr-create`, which does not exist (S-13), so the real path is named instead.

**Applies when:** Any merge request opened for ticket work.

**Does not apply when:** MRs opened by pipelines or bots (semantic-release).

**Replaces:** none
