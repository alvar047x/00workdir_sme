**Decided:** Read a ticket with `atpy jira fetch KEY`, then read `automation_tools/tickets/KEY/ticket-review.md`. Move status with `atpy jira transition KEY --status "<name>"`, set required fields first with `atpy jira set-fields KEY`, begin work with `atpy jira start KEY`. Comments are written in Markdown, never Jira wiki markup: `- ` bullets, `1.` numbered lists, backticks for code, `**bold**`, and `#` only at the start of a line that is meant to be a heading. Mention a person as `[~Full Name]` or `[~accountid:ID]`; the tool resolves the name through Jira user search and caches it in automation_tools/config/jira-users.json. Post with `atpy jira comment KEY "<text>"` and check the output for "mention not resolved".

**Because:** The comment command converts Markdown to ADF for API v3. Wiki markup (`{{x}}`, `* item`, `[~Name]` without support) rendered as raw text on a shared security ticket. The converter now emits real mention and numbered-list nodes, so the dialect and the mention form are the two facts that prevent a repeat.

**Applies when:** Any read, status change, or comment on a Jira ticket.

**Does not apply when:** Bulk sprint views, which use `atpy jira sprint` and `atpy sprint analyze`.
