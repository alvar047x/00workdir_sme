**Decided:** A push that is not a fast-forward is never forced silently. The push script prints a VERDICT HUMAN line with the exact force command and exits 2; the agent first offers the forward fix (reset to origin's tip, re-apply the file state as a new commit, push fast-forward). When the user says to force, their words go into the record's approval key and the push script runs the force with --force; the agent never runs git push --force by hand.

**Because:** The client layer denies a raw git push --force (S-11), and S-17 showed the forward fix usually reaches the same MR diff; but when a force is right, the user's yes should be enough, without the user running the command themselves (user, 2026-09-15).

**Applies when:** Backs the boolean force_push_is_human, now meaning the force needs the user's words in the record. Any push of a branch that already exists on the remote.

**Does not apply when:** A branch that has never been pushed, and a fast-forward push.
