**Decided:** Never write an AWS account number into a Jira ticket, a document, or anything an AI reads or stores. Refer to accounts by label and profile name instead: the Pexip enclave account (profile titan-pexip-prod), the Titan sandbox account (profile titan-admin), the networking account (profile awgov-networking), the DHA/Titan prod account (by hand only, id ending 775). Where an account id is embedded in a resource name, redact the digits and keep the rest, for example a state bucket written as <account-id>-tf-state-bucket. Local credential plumbing is out of scope: ~/.aws/config legitimately needs a literal sso_account_id per profile, AWS does not interpolate environment variables there, and it is not a ticket, doc or AI. Do not "fix" this by creating a .env of account ids in a project directory, which is strictly worse because project files are what agents read.

**Because:** Richard gave this as a direct instruction. Three findings comments posted on 2026-09-17 (DVPS-6799, 6804, 6812) contained account ids and had to be retro-sanitized on 2026-09-22; Jira retains comment edit history, so the originals stayed visible to ticket watchers for five days. The rule only works if it is applied before publishing, not after.

**Applies when:** Drafting or posting any Jira comment or ticket, writing wiki or repo documentation, logging to .sme, writing agent memory, or running any command whose output may carry an account id. AWS CLI output is the main leak path because ARNs embed the account id in nearly every response; pipe such output through sed -E 's/[0-9]{12}/<account-id>/g' so the value never enters context. Verify by aggregate only, a count of remaining matches, never by reading the content back.

**Does not apply when:** Editing ~/.aws/config or other local credential files, which must keep literal account ids to function.
