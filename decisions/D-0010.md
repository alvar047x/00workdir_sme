**Decided:** In terraform-aws-pexip-common every commit that should ship uses a conventional type (feat, fix, chore) because semantic-release derives the version bump from the commit type.

**Because:** The release job runs semantic-release on dev and platinum. A commit without a conventional type is ignored by the version calculation, so the change ships under no version or the wrong one. Intake shows 30 of the last 50 commits are non-conventional.

**Applies when:** Any commit on a branch that will merge to dev or platinum in terraform-aws-pexip-common.

**Does not apply when:** Commits semantic-release itself creates (chore(release): x.y.z). Other repos, which use the ticket-scoped form from the global semantic-commits decision.

**Replaces:** none
