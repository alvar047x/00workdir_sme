**Decided:** On any AWS auth failure (ExpiredToken, "SSO session associated with this profile has expired", AccessDenied on sts) the agent runs `aws sso login --sso-session amwell` itself, then re-verifies with `aws sts get-caller-identity --profile <target>`. Never `--no-browser`, never the Linux `timeout` wrapper, never tell the user to log in by hand.

**Because:** The agent runs on macOS with native browser SSO. The command is the agent's to run; the user clicks in the browser only if it asks, which it normally does not. Asking the user to log in wastes a turn and the old steering repeated this rule in three files because it kept being forgotten.

**Applies when:** Any aws, kubectl, skopeo, or terraform command that fails with an auth or expired-token error.

**Does not apply when:** The failure is a permissions error on a valid session (the profile lacks the right); that is a blocker to report, not a re-auth.
